Skills give your coding agent instructions for specific tasks. Dinvolt installs a recommended selection during project creation.

## What gets installed?

| Project | Skills cover |
| --- | --- |
| Every project | React, interface design, browser checks, shadcn/ui, transitions, changelogs and product documentation. |
| With an admin panel | Better Auth and the selected database provider. |

Skills are copied into `.agents/skills/` for Codex, Cursor and compatible agents, and `.claude/skills/` for Claude Code.

Commit those directories and `skills-lock.json` to share the same instructions with your team. The lockfile records sources and hashes.

To skip installation, use advanced configuration in the wizard or pass `--no-skills` during non-interactive creation.

## Use a skill

Name the skill in your request. For example:

```text
Use keep-a-changelog to review the changes, choose the next version
and update the changelog.
```

Your agent reads the installed skill and follows its workflow. Preparing release files does not commit, publish or deploy them.

## Start product documentation

```text
Use project-documentation to help me explain this product and create
concise Markdown context for future development.
```

The skill asks only for missing context: who the product serves, the problem it solves, its first workflow and future direction. It asks questions in your language and follows your documentation language preference.

It connects the root README, a task-based docs index, a product guide and `AGENTS.md`. Guides include `summary` and `read_when` metadata so agents can choose relevant context. Existing technical guides and project instructions are preserved.

With skills enabled, generated `AGENTS.md` asks the coding agent to offer this onboarding once when product context is missing. Starter setup guides do not count. Once docs exist, the agent replaces the suggestion with links. Declining also retires the suggestion; you can request the skill later.

## Update installed skills

Run this from your project:

<CodeGroup>

```sh npm
npx skills update
```

```sh bun
bunx skills update
```

```sh pnpm
pnpm dlx skills update
```

```sh yarn
yarn dlx skills update
```

</CodeGroup>

Review the changed instructions before committing. See the [Skills CLI documentation](https://skills.sh/docs/cli) for update options.

## Install Keep a Changelog separately

Dinvolt's **keep-a-changelog** skill also works in other repositories and stacks. It reviews changes, chooses a semantic version and updates `CHANGELOG.md` or `CHANGELOG.txt`.

<CodeGroup>

```sh npm
npx skills add nicoandrade/dinvolt --skill keep-a-changelog
```

```sh bun
bunx skills add nicoandrade/dinvolt --skill keep-a-changelog
```

```sh pnpm
pnpm dlx skills add nicoandrade/dinvolt --skill keep-a-changelog
```

```sh yarn
yarn dlx skills add nicoandrade/dinvolt --skill keep-a-changelog
```

</CodeGroup>

Then use the example request above. You can also ask for only an `Unreleased` entry or a specific version.

Browse the [skill source](https://github.com/nicoandrade/dinvolt/blob/main/skills/keep-a-changelog/SKILL.md) or the [full recommended selection](https://github.com/nicoandrade/dinvolt/blob/main/catalog/skills/config.json).
