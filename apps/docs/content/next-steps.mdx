## Public website only

You can start building right away. Describe your website to your coding agent, including its content and visual style:

```text wrap
Create a portfolio for a freelance designer with a project gallery,
an about section and a contact page. Use a clean layout, large typography
and warm colors.
```

Keep the development server running to see your changes. If you prefer editing directly, your homepage is `src/app/(public)/page.tsx`.

Add [UI components](/ui/blocks) as you need them. Database and administrator setup apply only to projects created with an admin panel.

<span id="public-website-with-administration"></span>

## Public website with an admin panel

Your public homepage is at `/`, and your panel's login is at `/admin`. The public site and panel have separate shadcn/ui profiles, so you can customize their styles independently.

Complete the [database and administrator setup](#set-up-your-admin-panel), then sign in at `/admin`. You should reach `/admin/home`; open **Users** to manage accounts at `/admin/users`.

For example, ask your coding agent:

```text wrap
Build a website for a photography studio with a gallery, services and a
contact page. Adapt the admin panel so the team can manage the gallery.
Use a minimal design that puts the photographs first.
```

Add public components with `--target public` and panel components with `--target admin`. See the [UI registry](/ui/blocks).

## Admin panel only

Your app starts at the login screen at `/`. After sign-in, administrators reach `/dashboard`; user management is at `/users`. There is no public homepage to configure.

Complete the [database and administrator setup](#set-up-your-admin-panel), then open your app's root URL, for example `https://my-app.localhost/`.

This project has one shadcn/ui profile and theme. Components live in `src/components/ui`; `dinvolt ui add` selects the admin profile automatically. You can also pass `--target admin` explicitly.

For example, ask your coding agent:

```text wrap
Read the project instructions. Build an internal inventory app with
products, stock movements and low-stock alerts. Extend the existing
dashboard and table controls, persist changes in the database, and
require administrator access for every query and mutation.
```

You can later deploy this app at `app.example.com` while keeping your marketing website in a separate project at `example.com`. Use the app's own origin for authentication; see [domains and environments](/guides/vercel/environments).

## Set up your admin panel

These steps apply to both **Public website + admin panel** and **Admin panel only**.

If you already connected your database and created an administrator in the wizard, skip to [signing in](#3-sign-in).

### 1. Create your database

Create an empty database with the provider you selected in Dinvolt. Use a development database for your first local setup.

| Provider | What you need from its dashboard |
| --- | --- |
| [Turso](https://turso.tech) | A Turso Database URL and authentication token. |
| [PlanetScale Postgres](https://planetscale.com/postgres) | An application connection URL (port 6432) and a direct connection URL (port 5432). |

Dinvolt connects to these services; you create the database in the provider's dashboard first. See [database setup](/guides/database) for credential names and manual configuration.

### 2. Complete setup

Run this from your generated project's folder:

<CodeGroup>

```sh npm
npx dinvolt setup
```

```sh bun
bunx dinvolt setup
```

```sh pnpm
pnpm dlx dinvolt setup
```

```sh yarn
yarn dlx dinvolt setup
```

</CodeGroup>

1. Select **development**, or add it if it was not selected during creation.
2. Enter the database credentials when prompted.
3. Wait for the summary to report **auth tables ready**.
4. Accept the offer to create the first administrator and enter a name and email.

Save the generated password when the wizard shows it. Restart the development server after setup so it picks up the new configuration.

Already have ready tables but skipped administrator creation? Run setup again to finish that step, or follow [Create the first administrator](/guides/authentication/administrators#create-the-first-administrator).

### 3. Sign in

Open the login URL for your project and sign in with your administrator's email and generated password:

| Project type | Local login example | Home after sign-in | Users |
| --- | --- | --- | --- |
| **Public website + admin panel** | `https://my-app.localhost/admin` | `/admin/home` | `/admin/users` |
| **Admin panel only** | `https://my-app.localhost/` | `/dashboard` | `/users` |

Password recovery needs [Resend and a sender](/guides/authentication/password-recovery). The included settings forms preview changes locally; connect your own authorized server operations to persist settings or uploads.

Use the [admin panel guide](/ui/admin-panel) when extending the included screens.
